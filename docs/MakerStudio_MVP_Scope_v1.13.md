## 0. 이 문서의 목적

외주 개발사/팀에게 위탁할 경우, **견적·계약·개발의 기준이 되는 "고정된 범위"** 를 정의합니다. 설계서(v2.4)에는 Phase 0~7 전체 로드맵이 있지만, "v1.0(첫 출시)에 정확히 무엇이 포함되는지"는 아직 선을 그은 적이 없었습니다. 이 문서가 그 선입니다.

**범위 확정 원칙**: §13.1(초기 타겟 = 개인 B2C 우선) 결정에 따라, **"개인 학습자가 가입해서 결제까지 할 수 있는 최소 단위"** 를 v1.0 기준으로 삼습니다. B2B(학교), 고급 게이미피케이션, AI 콘텐츠 자동화는 전부 v1.0 이후로 미룹니다.

## 1. MVP(v1.0) 범위 — 포함

### 화면 (프로토타입 대비)

**우선순위 표기 기준(MoSCoW)**: **Must**=법적 의무 등 제외 불가 · **Should**=핵심 동선, 뺄 경우 서비스가 안 됨 · **Could**=예산 되면 포함, 협상 시 1순위로 빠질 수 있는 항목 · **Won't**=v1.0에서 확실히 제외

|---|---|---|
| 랜딩페이지 | Should | §13 대응, SEO 진입점 |
| 로그인 (소셜) | Should | 구글 완료(2026-08-22). 카카오는 Supabase 대시보드 프로바이더 등록 대기, 네이버는 Could |

| 회원가입 (선생님, 이메일인증) | **Won't** | 학급코드·교사대시보드와 함께 Phase 4로 확정 연기 (2026-08-13) |

| 가격 정책 페이지 (`/pricing`) | Should | 2026-08-22 신설. Premium 메인/Family 보조 노출, 다크패턴 금지 원칙 적용, 출시 알림 신청(`waitlist_emails`) |

| 알림함 | Could | 결제 실패 알림만 Must 수준, 나머지 유형은 Could |
| 관리자 검수 | Should (비-UI 가능) | 화면 없이 DB 직접 수정으로도 충분 |
| 관리자 대시보드 (매출·구독자·이탈률) | Should | 이전엔 이 문서 어디에도 스코프되지 않았던 항목 — 2026-08-21 실제 구현(`app/admin/dashboard`). 상세는 `DB_Schema_v1.0.md` §2 "관리자 대시보드 집계 뷰" 참고 |
| 교사 대시보드 | Won't | Phase 4 |
| 평점·리뷰 | Won't | 여러 사용자 집계 데이터 필요, 초기엔 의미 작음 |
| 프로필 수정, 이메일 인증 | Should | |

**협상 팁**: Could 항목(위시리스트 영구저장, 알림 전체 유형, 배지/스트릭 고도화 등)을 견적 요청서(RFP)에는 포함해서 보내고, 견적이 예산을 초과하면 이 항목들부터 순서대로 빼면서 협상하는 걸 권장합니다 — Must/Should는 협상 대상에서 제외합니다.

## 3. 이 범위가 다음 문서에 미치는 영향
