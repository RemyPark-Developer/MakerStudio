## 0. 이 문서의 목적

설계서(§5, §7, §9, §12)에는 "빠르게", "안전하게", "테스트 없이 배포하지 않는다" 같은 **원칙**은 있지만, 외주 개발사가 견적을 내거나 완료 여부를 판단할 수 있는 **구체적인 숫자 기준**은 없었습니다. 이 문서가 그 숫자를 정의합니다. 각 항목은 어느 원칙에서 왔는지 출처를 표기합니다.

## 2. 확장성 / 트래픽 규모

§14.1(초기 타겟: 개인 B2C, 자체 마케팅 예산 제한적)을 감안한 **초기 규모 가정**입니다 — 이 숫자를 넘는 인프라를 미리 만들지 않습니다(과잉 설계 방지).

| 항목 | MVP 가정치 |
|---|---|
| 동시 접속자 | ~50명 (런칭 초기) |
| 일일 활성 사용자(DAU) | ~200명 |
| AI 튜터 일일 호출 | ~2,000회 (무료 10회 한도 × 활성 사용자 기준 상한) |
| DB 저장 용량 | 1GB 이하로 시작 (Supabase 무료/저가 티어로 충분) |

**원칙**: 이 규모를 크게 초과하는 부하 테스트나 오토스케일링 인프라는 MVP 범위에서 **Won't** — 실제 트래픽이 이 가정을 넘어서기 시작하면 그때 확장합니다.

## 8. 국제화(i18n) 준비도

- **MVP 범위**: 한국어만 실제 서비스, 번역 착수는 Won't (§13.2 미정 사항)
- **구현 시 필수**: `examples.label`/`intro` 등 다국어 대비 jsonb 구조(§6.2)는 **지금부터 지킬 것** — 나중에 번역만 추가하면 되도록. 문자열을 코드에 하드코딩하지 않고 `{ko: "...", en: ""}` 형태 유지

## 9. 테스트 / 품질 기준

§9(품질보증 원칙)를 구체적인 커버리지 숫자로 확정합니다.

| 항목 | 기준 |
|---|---|
| 결제·인증 관련 로직 | 단위 테스트 필수 (커버리지 목표 80% 이상) |
| 콘텐츠 검증 | `validate-content`, `validate-arduino` CI 게이트 필수 통과(이미 구현됨, §6.3) |
| E2E 테스트 | 최소 3개 핵심 시나리오: 회원가입→결제, AI튜터 질문, 계정삭제→환불계산. **⚠️ 2026-08-22 확인**: 커밋된 자동화 스위트(예: Playwright 테스트 파일, CI 연결)는 저장소에 없음 — 그동안 기능별로 Playwright를 임시 스크립트로 만들어 실DB로 검증한 뒤 스크립트를 지우는 방식으로 대체해왔음(각 세션 요약 문서의 "검증 방법" 참고). **매 기능마다 수동 재현이라 회귀 방지 효과가 없음** — CI에 상시 연결된 E2E 스위트가 필요해지면 별도 작업 |
| CI 필수 통과 | PR마다 테스트 실패 시 병합 차단(§9.1, 이미 GitHub Actions로 구현됨 — `validate-content`/`validate-arduino`/`npm test`(단위테스트)/`npm run build`(타입체크·빌드) 전부 CI 게이트에 포함돼 있음, `.github/workflows/ci.yml` 2026-08-22 재확인) |

## 10. 비용 상한 가이드 (참고용)

§14.1(빠른 매출 필요, 자본 여유 적음)을 반영해, 인프라 선택 시 다음을 우선합니다.

- Supabase, Vercel 모두 **무료/저가 티어로 MVP 트래픽(위 §2 가정치)을 충분히 커버** — 유료 상위 티어 선결제 금지
- AI 튜터 API 비용은 사용량 제한(§3)으로 상한선을 미리 걸어둠 — 예측 불가능한 비용 폭증 방지
- 이 상한을 넘는 시점(트래픽 증가)이 오히려 "매출이 늘고 있다"는 신호이므로, 그때 가서 인프라 업그레이드를 검토
